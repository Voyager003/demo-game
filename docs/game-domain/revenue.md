# 수입원 (Revenue)

## 수입원 개요

게임 내 수입원은 크게 네 가지 카테고리로 나뉜다.

1. **외주 프로젝트** (Contract Work)
2. **자체 서비스** (Own Product / SaaS)
3. **투자 유치** (Investment)
4. **추가 수입원** (Additional Revenue Streams)

---

## 외주 프로젝트 (Contract Work)

### 계약 구조

외주 프로젝트는 다음 항목으로 구성된다.

- **프로젝트명**: 계약 식별 이름
- **난이도**: Lv1 ~ Lv4
- **계약금액**: 전체 계약 금액
- **선금**: 계약금의 30% (계약 체결 즉시 지급)
- **잔금**: 계약금의 70% (납품 완료 후 지급, 만족도에 따라 보정)
- **소요 턴**: 프로젝트 완료까지 필요한 턴 수
- **요구 직군 / 스탯**: 프로젝트 수행에 필요한 직군 및 최소 스탯
- **클라이언트 성향**: 요구사항 변경 빈도, 소통 스타일 등에 영향

### 예시 계약서 포맷

```
┌─────────────────────────────────────┐
│         외주 프로젝트 계약서          │
├─────────────────────────────────────┤
│ 프로젝트명: [프로젝트 이름]           │
│ 난이도:     Lv[1~4]                  │
│ 계약금액:   [총액]                    │
│ 선금(30%):  [선금액]                  │
│ 잔금(70%):  [잔금액]                  │
│ 소요 턴:    [N턴]                     │
│ 요구 직군:  [직군 목록]               │
│ 요구 스탯:  [스탯 조건]               │
│ 클라이언트: [성향 유형]               │
└─────────────────────────────────────┘
```

### 외주 진행 중 이벤트

프로젝트 수행 도중 다양한 이벤트가 발생할 수 있다.

| 이벤트 | 발생 조건 | 결과 |
|--------|-----------|------|
| 요구사항 변경 | 클라이언트 성향 + 주사위 판정 | 작업량 +2턴, 추가비용 협상 가능 |
| 중간 납기 지연 | PM 부재 or 팀 케미 낮음 | 클라이언트 만족도 -10 |
| 팀원 번아웃 | 연속 야근 + 체력 낮음 | 해당 턴 생산성 0 |
| 서버 장애 | 보안감각 스탯 낮을 때 | 납기 +1턴, 명성 -5 |
| 품질 감동 납품 | 코드품질 + UI감각 높을 때 | 리퍼럴 이벤트 발생 |

### 클라이언트 만족도에 따른 수입 보정

납품 후 클라이언트 만족도에 따라 잔금 수령액과 추가 효과가 달라진다.

| 만족도 | 잔금 비율 | 추가 효과 |
|--------|-----------|-----------|
| 90~100 | 100% + 보너스 5% | 리퍼럴 클라이언트 1명 소개 |
| 70~89 | 100% | 없음 |
| 50~69 | 90% | 재계약 없음 |
| 30~49 | 70% (분쟁 발생) | 명성 -5 |
| 0~29 | 협상 또는 소송 | 명성 -15, 법률비용 발생 |

## 자체 서비스 (Own Product / SaaS)

### 서비스 수치

자체 서비스는 다음 핵심 수치로 관리된다.

| 수치 | 영문 키 | 설명 |
|------|---------|------|
| 완성도 | `Completeness` | 서비스의 기능 구현 정도 |
| UX 품질 | `UXQuality` | 사용자 경험 수준 |
| 안정성 | `Stability` | 서버/시스템 안정성 |
| 마케팅 노출도 | `MarketingExposure` | 외부 마케팅을 통한 인지도 |
| 서비스 평점 | `Rating` | 사용자 평점 (1.0 ~ 5.0) |

### 매출 공식

```
월간 구독 MAU = 기존 MAU x 유지율 + 신규 유입
신규 유입 = (마케팅 노출도 x 기본 전환율) x 서비스 평점 보정
월 매출 = MAU x ARPU (인당 평균 결제액)
```

### 서비스 이벤트 테이블

| 이벤트 | 발생 조건 | 결과 |
|--------|-----------|------|
| 바이럴 터짐 | 평점 4.5 이상 & 마케팅 높음 | MAU 200~500% 급등 |
| 1성 리뷰 폭탄 | 완성도 낮음 + 마케팅 과투자 | 평점 급락 |
| 경쟁 서비스 출시 | 랜덤 발생 | MAU 성장 둔화 |
| 언론 기사 | 명성 70 이상 | MAU +30% |
| 서버 다운 | 안정성 낮음 + 트래픽 급등 | 평점 -0.5, 이탈 5~15% |
| 대규모 업데이트 | 플레이어 지시 | 완성도 상승, 일시적 버그 증가 |
| 정부 지원사업 | 명성 60 이상 + 특정 카테고리 | 보조금 지급 + 명성 +10 |

## 추가 수입원

### 정부/기관 지원사업

- **공고 주기**: 8~12턴마다 발생
- **지원금 규모**: 2,000만 ~ 2억
- **비용**: PM 1명이 1턴 소모 (서류 작업)

### 기술 라이선싱

- **조건**: CTO 재직 중 + 개발자 스탯 합계 100 이상
- **수입**: 계약금 1억~5억 + 로열티 수입
- **리스크**: 기술 유출 가능성

### 외부 강연 / 콘텐츠

- **조건**: 명성 65 이상
- **수입**: 강연료 + 명성 +5
- **테크블로그 운영 시**: 광고수익 + 명성 상승 + 채용 효율 증가

### 파트너십 / 제휴

- **조건**: 명성 50 이상
- **유형**: 공동 마케팅 or 데이터 파트너십
- **리스크**: 개인정보 이슈 발생 가능성

### 단기 대출

- **활성화 조건**: 보유 자본 500만 이하
- **한도**: 보유 자산의 50%
- **월 이자**: 3~8%
- **상환 기간**: 8~12턴
