# 채용/직군 (Career)

## 개요

직원은 회사의 핵심 자원이다. 각 직원은 고용 형태, 공통 스탯, 직군별 전문 스탯을 보유하며, 이력서 시스템을 통해 채용된다.

---

## 고용 형태

### 수습직
- **수습 기간**: 12주 (12턴)
- **생산성**: 정규직 대비 **70~85%**
- **해고 제한**: 수습 기간 중 해고 시 명성(Reputation) **-5**
- 수습 기간 동안 직원의 숨겨진 특성이 점진적으로 공개된다.

### 정규직
- 수습 12턴 완료 후 **전환 선택** 이벤트가 발생한다.
- **전환 수락 시**: 연봉 협상 이벤트 발생 가능. 정규직 전환과 동시에 생산성 100%로 전환.
- **전환 거부 시**: 자동 퇴사 처리. 해당 팀의 케미스트리에 일시적 영향 발생.

---

## 공통 스탯

모든 직원은 직군과 무관하게 다음 5개의 공통 스탯을 보유한다.

| 스탯 | 설명 | 범위 |
|------|------|------|
| **체력 (Stamina)** | 야근 감내 능력, 번아웃 저항 | 1~10 |
| **커뮤니케이션 (Communication)** | 협업 효율, 오해 발생 빈도 | 1~10 |
| **멘탈 (Mental)** | 스트레스 저항, 돌발 이벤트 대응력 | 1~10 |
| **성장속도 (GrowthRate)** | 매 N턴마다 전문 스탯 자동 증가율 | 1~10 |
| **충성도 (Loyalty)** | 이직 확률, 갈등 시 이탈 저항력 | 1~10 |

### 공통 스탯 상세

- **체력 (Stamina)**: 체력이 낮은 직원은 크런치(야근) 투입 시 번아웃 확률이 급격히 상승한다.
- **커뮤니케이션 (Communication)**: 팀 내 협업 효율에 직접 영향. 수치가 낮으면 업무 전달 시 오해가 발생하여 재작업 확률이 올라간다.
- **멘탈 (Mental)**: 스트레스 수치 증가에 대한 저항력. 돌발 이벤트(버그 폭발, 클라이언트 컴플레인 등) 발생 시 성과 하락 폭을 줄인다.
- **성장속도 (GrowthRate)**: 전문 스탯이 자동으로 증가하는 속도를 결정한다. 성장속도가 높을수록 적은 턴 수로 전문 스탯이 올라간다.
- **충성도 (Loyalty)**: 헤드헌팅 이벤트나 팀 내 갈등 발생 시 이탈 확률에 영향. 충성도가 낮은 직원은 연봉 불만족 시 즉시 이직할 수 있다.

## 직군 1: 개발자 (Developer)

회사의 기술적 핵심. 프로젝트의 실질적 구현을 담당한다.

### 전문 스탯

| 스탯 | 설명 |
|------|------|
| **구현속도 (CodingSpeed)** | 코드 작성 및 기능 구현 속도 |
| **코드품질 (CodeQuality)** | 버그 발생률, 유지보수 용이성 |
| **문제해결력 (ProblemSolving)** | 기술적 난관 돌파, 디버깅 효율 |
| **기술스택폭 (TechBreadth)** | 다양한 기술 스택 대응 능력 |
| **보안감각 (SecuritySense)** | 보안 취약점 사전 방지, 보안 이슈 대응 |

### 프로젝트 난이도 티어

전문 스탯 5개의 합산 수치로 수행 가능한 프로젝트 난이도가 결정된다.

| 티어 | 스탯 합산 | 프로젝트 예시 |
|------|----------|-------------|
| **Lv1** | 10~19 | 랜딩페이지, 단순 관리자 페이지 |
| **Lv2** | 20~34 | 커머스, 예약 시스템 |
| **Lv3** | 35~49 | 플랫폼, 실시간 기능 (채팅, 알림) |
| **Lv4** | 50+ | AI 연동, 대규모 트래픽 처리 시스템 |

> 팀에 배정된 개발자들의 스탯 합산이 프로젝트 요구 티어에 미달하면 품질 저하 및 딜레이 패널티가 발생한다.

---

## 직군 2: 디자이너 (Designer)

제품의 시각적 품질과 사용자 경험을 담당한다.

### 전문 스탯

| 스탯 | 설명 |
|------|------|
| **UI감각 (UISense)** | 시각적 완성도, 디자인 퀄리티 |
| **UX사고력 (UXThinking)** | 사용자 흐름 설계, 사용성 개선 |
| **작업속도 (WorkSpeed)** | 디자인 산출물 작업 속도 |
| **브랜딩감각 (BrandingSense)** | 브랜드 아이덴티티 구축, 일관성 유지 |
| **프로토타이핑 (Prototyping)** | 프로토타입 제작 속도 및 완성도 |

### 디자이너 역할
- 프로젝트 시작 단계에서 디자인 산출물을 생성한다.
- 디자이너가 없는 프로젝트는 UI 품질 페널티가 적용된다.
- 브랜딩감각이 높은 디자이너는 자체 서비스의 브랜드 가치에 기여한다.

## 직군 3: PM (Project Manager)

프로젝트 일정과 품질을 관리하며, 클라이언트와의 소통을 담당한다.

### 전문 스탯

| 스탯 | 설명 |
|------|------|
| **일정관리 (ScheduleManagement)** | 프로젝트 일정 수립 및 준수율 |
| **요구사항분석 (RequirementAnalysis)** | 클라이언트 요구사항의 정확한 파악 |
| **리스크감지 (RiskDetection)** | 잠재적 위험 요소 사전 식별 |
| **고객응대 (ClientManagement)** | 클라이언트 만족도, 컴플레인 대응 |
| **팀조율력 (TeamCoordination)** | 팀원 간 업무 배분 및 갈등 조율 |

### PM 부재 시 패널티

PM이 배정되지 않은 프로젝트에는 다음 패널티가 매 프로젝트 턴마다 적용된다.

| 패널티 항목 | 수치 |
|------------|------|
| **딜레이** | +15% |
| **재작업** | +10% |

> PM이 없으면 일정 관리가 느슨해지고, 요구사항 오해로 인한 재작업이 빈번해진다.

## 직군 4: 이사진 (C-Level)

경영진으로서 회사 전체에 영향을 미치는 버프를 제공한다.

| 포지션 | 역할 | 효과 |
|--------|------|------|
| **CTO** | 기술 방향 결정 | 개발 스탯 전체 **+10%** |
| **CMO** | 마케팅 효율 | 마케팅비 효과 **+20%** |
| **COO** | 운영비 최적화 | 고정 지출 **-5~15%** |
| **CFO** | 투자 유치 | 투자 심사 조건 **열람 가능** |

### 이사진 특성
- **출현율**: 이력서 풀에서 이사진 후보는 일반 직원의 **1/5** 확률로 등장한다.
- **채용 조건**: 스케일업 단계 (16명 이상)부터 이사진 채용이 가능하다.
- **연봉**: 일반 직원 대비 2~3배 수준의 높은 연봉을 요구한다.
- **복수 채용**: 동일 포지션에 복수 채용은 불가하다 (CTO는 1명만 가능).

## 이력서 시스템

직원 채용은 이력서 시스템을 통해 이루어진다.

### 이력서 생성 규칙
- 매 **채용 턴**마다 **3~5장**의 이력서가 자동 생성된다.
- 회사 **명성(Reputation)**에 따라 이력서 퀄리티 분포가 변동한다.
  - 명성 높음: 고스펙 이력서 비율 증가
  - 명성 낮음: 저스펙 이력서 위주로 생성

### 이력서 구성 항목

| 항목 | 설명 | 공개 여부 |
|------|------|----------|
| **이름** | 지원자 이름 | 공개 |
| **직군** | 개발자 / 디자이너 / PM / 이사진 | 공개 |
| **경력** | 경력 연차 | 공개 |
| **전문 스탯** | 직군별 전문 스탯 수치 | 공개 |
| **기본 스탯** | 공통 스탯 수치 | 공개 |
| **특성** | 보유 특성 목록 | **일부만 공개** |
| **희망 연봉** | 지원자가 요구하는 연봉 | 공개 |

> 특성은 이력서에 일부만 표시되며, 나머지는 수습 기간 중 점진적으로 드러난다.
