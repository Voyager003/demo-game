# 2026-04-23 작업 로그

## 작업 주제
- 투자 유치 이벤트를 경제 도메인 하위에 추가
- 객체 지향적으로 투자 심사 정책과 결과 적용 로직 분리
- 결정론 레이어와 확률 레이어를 함께 사용하는 투자 심사 흐름 도입

## 오늘 반영한 내용
- `companyRating`을 `GameState`에 추가
- 투자 상태 객체 `investment`를 `GameState`에 추가
- 투자 액션 `startInvestmentRound` 추가
- 투자 흐름을 `행동 시작 -> 심사 대기 -> 결과 이벤트` 3단계로 구현
- 투자 심사 계산을 `InvestmentReviewPolicy`로 분리
- 투자 결과 적용을 `InvestmentResultResolver`로 분리
- 투자 결과를 `investmentResult` 이벤트로 노출
- 채용 공고의 이력서 품질 계산이 고정값이 아니라 `companyRating`을 참조하도록 변경
- 투자 성공 시 자본 유입, `companyRating` 상승, 전 직원 `loyalty +1`, `growthRate +1` 적용
- 투자 실패 시 `companyRating` 하락, 재도전 쿨다운 적용

## 주요 의사결정
- 투자 유치는 독립 대도메인이 아니라 `경제 도메인 하위`로 둔다.
- v1에서는 현재 런타임에 이미 있는 상태 위주로 투자 심사를 구성한다.
- 투자 진입은 대표 행동으로 시작한다.
- 투자 결과는 즉시 처리하지 않고 심사 대기 후 이벤트로 처리한다.
- 투자 판정은 순수 결정론이 아니라 `결정론 점수 -> 확률 레이어 판정` 구조를 쓴다.
- 회사 수준 평판/신뢰는 `companyRating` 단일 수치로 축약한다.
- `포텐셜`은 독립 상태가 아니라 `비전 + 실적 + 반복 수입`의 합성 개념으로 계산한다.
- 투자 성공 보상은 별도 버프 객체를 만들지 않고 기존 직원 공통 스탯에 직접 반영한다.

## 구현 메모
- 결정론 입력:
  - `CEO vision`
  - `completedProjectCount`
  - `주수입원 실효 수입`
  - `companyRating`
- 확률 레이어는 이번 작업에서 투자 심사에만 적용했다.
- 투자 결과 로그에는 결정론 trace와 확률 trace가 모두 남도록 했다.
- 투자 결과 이벤트는 기존 `pendingEvents` / `EventModal` 구조를 재사용했다.
