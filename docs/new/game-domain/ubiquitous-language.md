# 유비쿼터스 언어 (Ubiquitous Language)

이 문서는 `docs/old/mvp-core-loop.md`를 기준으로 **문서에서 같은 개념을 같은 이름으로 부르기 위한 표준 용어집**입니다.

기본 원칙:
- 한국어를 우선으로 쓴다.
- 코드에서 실제로 쓰는 용어는 함께 적는다.
- 문서 전용 설계 개념은 `문서 전용`으로 명시한다.
- 서로 다른 개념을 같은 말로 부르지 않는다.

---

## 표기 원칙

1. 본문 표준 용어는 한국어를 사용한다.
2. 코드 용어는 괄호나 표에서만 보조 표기로 적는다.
3. 플레이어가 보는 개념과 내부 코드 개념이 다르면 둘 다 명시한다.
4. 현재 구현과 미래 설계를 섞지 않는다.
5. 혼용이 잦은 말은 아래 `혼용 정리`를 기준으로 통일한다.

---

## 0순위 용어

| 표준 용어 | 코드 용어 | 현재 상태 | 설명 |
|----------|-----------|----------|------|
| **턴** | `turn` | 구현됨 | 게임 진행의 가장 큰 시간 단위 |
| **페이즈** | `phase`, `TurnPhase`, `TurnCycle` | 구현됨 | 한 턴 안의 5단계 순서 |
| **행동** | `ActionType` | 구현됨 | 대표가 의사결정 페이즈에서 선택하는 유료 행동 |
| **피로도** | `FatigueState`, `FatigueMeter` | 구현됨 | 한 턴에 행동을 얼마나 더 할 수 있는지 보여주는 자원 |
| **쿨타임** | `FatigueState.cooldowns`, `ACTION_RULES` | 구현됨 | 특정 행동을 다시 쓰기 전까지 기다려야 하는 턴 수 |
| **직원** | `Employee` | 구현됨 | 회사에 소속되어 프로젝트에 배정되는 사람 |
| **직군** | `Role` | 구현됨 | 직원의 전문 역할. 현재는 개발자, 디자이너, PM |
| **전문 스탯** | `specialistStats` | 구현됨 | 프로젝트 진척과 품질 계산에 직접 쓰는 직군별 스탯 |
| **업무 배정** | `assignedEmployeeIds`, `projectAssignments` | 구현됨 | 어떤 직원이 어떤 프로젝트에 투입되는지 나타내는 상태 |
| **프로젝트** | `Project` | 구현됨 | 회사가 수행하거나 운영하는 일의 기본 단위 |
| **외주 프로젝트** | `Project.kind='contract'` | 구현됨 | 선금과 잔금이 있는 클라이언트 계약 프로젝트 |
| **주수입원 프로젝트** | `Project.kind='ownedProduct'`, `isMainRevenue=true` | 구현됨 | 게임 시작 시 도메인 선택으로 생성되는 프로젝트의 한 종류. 월 반복 수입을 만든다 |
| **진척도** | `progress`, `project.progressPerTurn` | 구현됨 | 프로젝트가 얼마나 완료에 가까운지 나타내는 수치 |
| **클라이언트 만족도** | `clientSatisfaction` | 구현됨 | 납품 결과에 따라 잔금 보정에 영향을 주는 수치 |
| **자본** | `capital` | 구현됨 | 회사가 현재 보유한 현금성 자원 |
| **선금** | `ContractPaymentTerms.advance()`, `advancePaid` | 구현됨 | 외주 계약 시 먼저 받는 30% 수입 |
| **잔금** | `EconomyLedger.finalPayment()`, `finalPaid` | 구현됨 | 납품 완료 후 받는 나머지 수입 |
| **월 반복 수입** | `monthlyRevenue`, `economy.recurringRevenue` | 구현됨 | 주수입원 프로젝트가 정산 단계에서 만들어내는 반복 수입 |
| **연봉** | `salary` | 구현됨 | 직원 1명의 연 단위 보상 금액 |
| **운영비** | `EconomyLedger.monthlyOperatingCosts()` | 구현됨 | 회사 운영에 따라 자동으로 빠지는 고정 비용 |

## 1순위 용어

| 표준 용어 | 코드 용어 | 현재 상태 | 설명 |
|----------|-----------|----------|------|
| **대표** | `CEO`, `ceo` | 구현됨 | 플레이어가 조작하는 회사의 대표 |
| **도메인** | `Domain` | 구현됨 | 게임 시작 시 선택하는 회사 분야 |
| **대표 스탯** | `CeoStats` | 구현됨 | 대표의 리더십, 협상력, 비전, 기술 이해도, 위기 대응력 |
| **채용 후보** | `pendingResumes: Employee[]` | 구현됨 | 아직 채용되지 않았지만 채용 풀에 올라온 사람 |
| **이력서** | `pendingResumes`, `EmployeeFactory.generateResumes()` | 구현됨 | 채용 후보를 플레이어가 읽는 화면/목록 단위 |
| **채용 공고** | `postJobListing` | 구현됨 | 채용 후보 풀을 생성하는 행동 |
| **면접 및 채용 확정** | `conductInterview` | 구현됨 | 채용 후보를 직원으로 전환하는 행동 |
| **수습** | `probationTurnsLeft > 0` | 구현됨 | 정규직 직원의 초기 적응 상태 |
| **수습 전환** | `probationConversion` | 구현됨 | 수습 종료 후 정규직 유지 여부를 결정하는 이벤트 |
| **직원 공통 스탯** | `commonStats` | 구현됨 | 체력, 커뮤니케이션, 멘탈, 성장속도, 충성도 |
| **충성도** | `commonStats.loyalty` | 구현됨 | 직원이 회사를 떠나지 않고 남으려는 정도 |
| **연봉 협상** | `salaryNegotiation` | 구현됨 | 연봉 인상 요구 이벤트 |
| **납기 임박 알림** | `deadlineApproaching` | 구현됨 | 프로젝트 마감이 가까워졌음을 알리는 이벤트 |
| **자본 위기 경고** | `capitalCrisis` | 구현됨 | 자본이 낮아졌음을 알리는 경고 이벤트 |
| **위기 상태** | `gameStatus='crisis'` | 구현됨 | 자본 고갈 이후 유예 턴을 소비하는 생존 상태 |
| **유예 턴** | `crisisGraceTurnsLeft` | 구현됨 | 위기 상태에서 회복 기회로 주어지는 남은 턴 수 |
| **엔딩 등급** | `endingGrade` | 구현됨 | 게임 종료 시 평가 등급 |
| **특성** | 코드 용어 없음 | 문서 전용 | 직원의 성향과 숨은 변수 |
| **팀 케미** | 코드 용어 없음 | 문서 전용 | 팀 분위기와 상호작용의 품질을 나타내는 설계 개념 |

## 혼용 정리

| 혼용되는 표현 | 표준 용어 | 이유 |
|--------------|----------|------|
| 대표(CEO), CEO, Player | **대표** | 플레이어가 읽는 기준에서는 대표가 가장 자연스럽다 |
| 회사 카테고리, 분야, 카테고리 | **도메인** | 코드에서 `Domain`으로 관리하며 게임 시작 선택과 직접 연결된다 |
| 외주, 계약, 클라이언트 일 | **외주 프로젝트** | 수입 구조와 프로젝트 엔티티를 동시에 설명할 수 있다 |
| 주수입원, 자체 서비스, 운영 서비스 | **주수입원 프로젝트** | 현재 MVP 구현에서 `프로젝트의 한 종류`로 다뤄지기 때문이다 |
| 직원 배정, 배분, assignment | **업무 배정** | 사람을 프로젝트에 투입하는 상태를 가장 직접적으로 설명한다 |
| 지원자, 후보, 이력서 | **채용 후보** / **이력서** | 사람은 채용 후보, 그 사람을 보여주는 항목은 이력서로 분리한다 |

## 문서에 있으나 현재 MVP 핵심 용어가 아닌 것

| 용어 묶음 | 현재 위치 | 메모 |
|----------|----------|------|
| 투자 라운드, 투자사, 시리즈 | [투자](../../old/game-domain/invest.md) | Post-MVP 성장 도메인 |
| MAU, ARPU, 평점, 마케팅 노출도 | [수입원](../../old/game-domain/revenue.md) | 서비스형 확장 설계 용어 |
| 복지비, 마케팅비 | [지출](../../old/game-domain/cost.md) | 현재 코어 루프의 필수 비용은 아님 |
| 기술 부채, 리팩토링 | [기술](../../old/game-domain/tech.md) | 장기 운영 단계 도메인 |
| 시장 트렌드, 규제 이벤트 | [이벤트 카탈로그](../../old/game-domain/event-catalog.md) | 외부 환경 확장 도메인 |
