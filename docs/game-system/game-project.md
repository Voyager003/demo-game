# 프로젝트 시스템 (Game Project)

## 1. 프로젝트 유형

| 유형 | 성격 | 수익 모델 |
|------|------|-----------|
| 외주 프로젝트 (Contract Work) | 단발성 | 계약금 기반 (선금 + 잔금) |
| 자체 서비스 (Own Product) | 지속성 | MAU/구독 기반 월 매출 |
| 리팩토링 프로젝트 | 내부 개선 | 수익 없음 (기술 부채 해소 목적) |

---

## 2. 외주 프로젝트 진행

### 진행 흐름

```
계약 체결 (피로도 3, 쿨타임 1턴) → 선금 30% 수령
  ↓
개발 진행 (자동, Execution Phase에서 매 턴 진척)
  ↓ 진행 중 이벤트 발생 가능 (요구사항 변경, 장애 등)
납품 완료 → 클라이언트 만족도 계산
  ↓
잔금 70% × 만족도 보정 수령
```

### 프로젝트 난이도 티어

팀 전문 스탯 합산에 따라 수주 가능한 프로젝트 난이도가 결정된다.

| 티어 | 요구 수준 | 비고 |
|------|-----------|------|
| Lv1 | 낮음 | 초기 팀에서 수주 가능 |
| Lv2 | 중간 | 중급 인력 필요 |
| Lv3 | 높음 | 시니어급 인력 필요 |
| Lv4 | 매우 높음 | 전문 팀 구성 필요 |

상세 → [채용/직군](../game-domain/career.md) 참조

### 진척도 계산

```
매 턴 진척도 = 투입 인력의 관련 스탯 합산 × 생산성 보정
```

### 생산성 보정 요인

| 요인 | 영향 |
|------|------|
| 팀 케미 | 높을수록 보정 증가 |
| PM 유무 | PM 부재 시 딜레이/재작업 확률 증가 |
| 야근 여부 | 단기 생산성 증가, 체력 소모 가속 |
| 특성 효과 | 직원 개인 특성에 따른 보정 |
| 기술 부채 패널티 | 기술 부채 높을수록 생산성 감소 |

---

## 3. 자체 서비스 개발

### 서비스 수치 5종

| 수치 | 영향 요소 | 역할 |
|------|-----------|------|
| 완성도 (Completeness) | 개발자 코드품질, PM 요구사항분석 | 기능 충족도 |
| UX품질 (UXQuality) | 디자이너 UX사고력 | 사용자 경험 |
| 안정성 (Stability) | 보안감각, 인프라 지출 | 장애 빈도 |
| 마케팅노출도 (MarketingExposure) | 마케팅비 지출량 | MAU 증가율 |
| 서비스평점 (Rating) | 완성도 × UX품질 ± 이벤트 | 유저 리뷰 |

### MAU 계산 공식

```
월간 MAU = 기존 MAU × 유지율 + 신규 유입
신규 유입 = (마케팅 노출도 × 기본 전환율) × 서비스 평점 보정
월 매출 = MAU × ARPU
```

## 4. 기술 부채 메커니즘

### 범위

0 ~ 100

### 누적 조건

| 조건 | 증가량 |
|------|--------|
| 납기 단축 | +5 ~ +15 |
| 속도제일주의 특성 | +3 |
| 야근 연속 | +2/턴 |
| 코드리뷰 생략 | +5 |

### 감소 조건

| 조건 | 감소량 |
|------|--------|
| 리팩토링 완료 | -20 ~ -40 |

### 구간별 페널티

구간별 상세 페널티 → [기술](../game-domain/tech.md) 참조

### 리팩토링 프로젝트

- 소요 기간: 4~12턴
- 수익: 없음
- 완료 효과: 기술 부채 대폭 감소, 생산성 +10%

---

## 5. 업무 배분 시스템 (Work Allocation)

### 기본 규칙

- 직원별 리소스 = 총 100%
- 100% 초과 배분 불가
- 50% 미만 투입: 해당 프로젝트 생산성 비례 감소
- 복수 프로젝트 동시 투입: 컨텍스트 스위칭 패널티 -5% ~ -10%

### 배분 예시

```
직원별 리소스 = 총 100%

- 개발자 A: 외주 X 70% + 자체 서비스 30%
- 개발자 B: 외주 X 100%
- 디자이너 C: 자체 서비스 50% + 브랜딩 50%
```

---

## 6. PM 부재 패널티

PM(프로젝트 매니저)을 배치하지 않은 프로젝트에는 다음 패널티가 적용된다.

| 패널티 | 수치 |
|--------|------|
| 딜레이 발생 확률 | +15%/턴 |
| 재작업 발생 확률 | +10%/턴 |

PM 배치 시 위 패널티 완전 해소 (결정론적 레이어).
